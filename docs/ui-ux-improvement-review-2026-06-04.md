# Class Sync UI/UX 및 기능 개선 검토 보고서

- 작성일: 2026-06-04
- 대상: Obsidian 플러그인 `class-sync`
- 검토 관점: 베타 사용자 온보딩, 교사용 운영 UX, 학생 UX, 상태/진단 화면, 배포 전 문서 완성도
- 확인 범위: `README.md`, `src/settings`, `src/ui`, `src/ui/panel`, `styles.css`, `docs`, `assets`

## 요약

현재 Class Sync는 개인 미러링, QR 초대, 공유 폴더, Yjs 실시간 편집, Excalidraw 연동, 피드백 레이어, 모바일 보호까지 기능 범위가 충분히 넓다. 코드상으로도 설정 그룹, 통합 패널, 진단/로그, 파괴적 초기화 확인, 초대 코드 보안 경고 등 베타 운영에 필요한 기본 장치는 잘 갖춰져 있다.

다만 베타 사용자 관점에서는 기능이 많은 만큼 "다음에 무엇을 해야 하는지"가 한눈에 보이지 않는다. 특히 교사 최초 설정, 학생 대량 등록, 초대/배포, 오류 복구, 피드백 운영 흐름이 아직 설정 항목과 버튼 묶음 중심이라 실제 교실에서 사용자가 길을 잃을 가능성이 있다.

가장 큰 개선 방향은 새로운 동기화 기능을 더 추가하는 것보다, 이미 구현된 기능을 교사와 학생이 안전하게 따라갈 수 있도록 온보딩과 상태 화면을 제품화하는 것이다.

## 주요 권장 사항

### P1. 교사용 최초 설정 마법사 추가

- 위치: `src/settings/SettingsTab.ts:34-48`
- 관련 위치: `src/ui/RoleSetupModal.ts:23-59`

현재 역할 선택 후에는 설정 탭에서 학급, 관리자 계정, 학생 목록, 공유 공간, Yjs, 동기화 옵션, 백업, 초기화가 순서대로 모두 렌더링된다. 기능은 충실하지만, 처음 설치한 교사가 어떤 순서로 해야 하는지 UI가 명확히 안내하지 않는다.

권장 UX:

1. 서버 연결: CouchDB URL, 관리자 계정 입력, 연결 테스트.
2. 학급 정보: 학급 ID, 교사 표시 이름.
3. 학생 등록: 한 명 추가 또는 명단 붙여넣기.
4. 학생 초대: QR/코드 표시, 초대 완료 상태 확인.
5. 첫 동기화 테스트: 샘플 노트 또는 선택 파일로 왕복 확인.
6. 완료: 패널 열기, 상태 대시보드 안내.

구현 방향:

- 기존 설정 탭은 고급 설정으로 유지한다.
- `RoleSetupModal`에서 Teacher Mode 선택 시 바로 `TeacherSetupWizardModal` 또는 패널의 `setup` 탭으로 이동한다.
- `settings.setupComplete`와 별개로 `teacherOnboardingComplete` 같은 상태를 둘 수 있다.
- 마법사는 서버/학생/초대/테스트 완료 여부를 체크리스트로 표시하고, 사용자가 중간에 닫아도 이어서 진행할 수 있게 한다.

기대 효과:

- 베타 사용자 첫 성공률 상승.
- README를 계속 보지 않아도 플러그인 안에서 설정 순서를 이해할 수 있음.
- 교사용 지원 문의 감소.

### P1. 동기화 상태 탭을 액션형 대시보드로 확장

- 위치: `src/ui/PanelView.ts:31-126`
- 위치: `src/ui/panel/SyncStatusSection.ts:29-121`

통합 패널은 좋은 방향이다. 다만 기본 진입점인 동기화 상태 탭은 현재 "전체 동기화 / 업로드만 / 다운로드만 / 자동 동기화 / 충돌 목록" 버튼과 링크별 표 중심이다. 오류가 있거나 초대가 덜 된 상태에서 사용자가 눌러야 할 다음 행동은 직접 추론해야 한다.

권장 UX:

- 상단 요약:
  - 전체 상태: 정상 / 조치 필요 / 오프라인 / 자동 동기화 꺼짐.
  - 학생 수, 초대 완료 수, 공유 공간 수, 충돌 수.
  - 마지막 성공 동기화 시각.
- 조치 카드:
  - "초대가 필요한 학생 3명" → 학생 설정/초대 버튼.
  - "충돌 2건" → 충돌 목록 열기.
  - "오프라인 1명" → 연결/권한 테스트.
  - "실시간 토큰 없음" → 실시간 설정 또는 재배포.
- 표의 내부 정보 정리:
  - 기본 표시: 학생 이름, 상태, 마지막 수신, 충돌.
  - 고급 펼침: Mirror DB, localRoot, 상세 오류.

구현 방향:

- `SyncStatusSection.renderTable()`에서 `rows`를 기반으로 summary model을 계산한다.
- 상태별 CTA를 `PanelHost` 메서드와 연결한다.
- 현재 `lastError`는 툴팁에만 있으므로, 오류 행에서는 짧은 메시지를 보이는 영역에도 표시한다.

기대 효과:

- 교사가 패널만 보고 학급 상태를 운영할 수 있음.
- 로그를 읽지 않아도 다음 액션이 명확함.

### P1. 모바일/좁은 사이드바 레이아웃 개선

- 위치: `styles.css:41-72`
- 위치: `styles.css:150-162`
- 위치: `src/ui/panel/SyncStatusSection.ts:85-121`

대시보드 표는 `white-space: nowrap` 기반이라 좁은 오른쪽 사이드바나 모바일에서 가로 스크롤 의존도가 높다. 베타에서 모바일 지원을 강조하는 만큼 상태 확인과 피드백/배포 화면은 작은 화면에서도 자연스러워야 한다.

권장 UX:

- 좁은 폭에서는 테이블 대신 학생별 카드 리스트로 전환.
- 각 카드에는 학생 이름, 상태 배지, 마지막 동기화, 충돌 수, 오류 요약만 표시.
- 상세 정보는 펼침 영역으로 제공.
- 패널 탭은 텍스트가 줄바꿈되더라도 터치 타겟이 36px 이상 유지되게 조정.

구현 방향:

- CSS media query로 `.class-sync-dash-table`을 숨기고 `.class-sync-dash-cards`를 표시한다.
- `SyncStatusSection`에서 table과 card markup을 함께 렌더하거나, CSS grid로 동일 데이터를 카드화한다.
- 버튼 묶음은 핵심 액션만 먼저 보이고 나머지는 관리 탭으로 이동하는 식으로 밀도를 낮춘다.

기대 효과:

- 모바일 교사/학생이 상태를 확인하기 쉬워짐.
- 오른쪽 사이드바를 좁게 쓰는 데스크톱 사용자에게도 읽기 쉬움.

## 교사용 운영 기능 제안

### P2. 학생 명단 일괄 추가

- 위치: `src/settings/SettingsTab.ts:101-118`
- 관련 위치: `src/settings/SettingsTab.ts:269-311`

현재 학생은 `+ 학생 추가` 버튼으로 한 명씩 카드에 입력한다. 실제 교실에서는 20~30명 명단을 다루므로 이 흐름은 초기 설정의 가장 큰 마찰이 될 수 있다.

권장 기능:

- 이름/ID 줄붙여넣기:
  - `홍길동,hong`
  - `김학생 kim_student`
  - 이름만 있으면 ID 자동 생성.
- CSV import.
- 중복 ID/DB명 검증.
- 일괄 초대 생성:
  - 학생별 QR을 순서대로 표시.
  - 또는 인쇄 가능한 초대 코드 시트 생성.

구현 방향:

- `StudentBulkImportModal` 추가.
- `StudentConfig[]` 생성 전에 normalization과 validation을 수행한다.
- `studentId`, `remoteDb`, `localRoot` 충돌을 UI에서 미리 보여준다.

### P2. 배포 전 미리보기와 결과 리포트

- 위치: `src/ui/panel/DeploySection.ts:36-160`
- 관련 위치: `src/modes/teacher/BulkCopy.ts`

배포 탭은 현재 원본 경로, 대상 경로, 기존 파일 처리, 대상 학생 선택 후 바로 실행한다. 복사 결과는 `Notice`의 작성/건너뜀 수만 보여준다.

권장 UX:

- 실행 전 dry-run:
  - 학생별 최종 대상 경로.
  - 기존 파일 존재 여부.
  - 건너뜀/덮어쓰기/새 이름 예상.
  - 템플릿 변수 치환 결과 일부 미리보기.
- 실행 후 상세 결과:
  - 학생별 성공/건너뜀/실패.
  - 실패 항목만 다시 시도.
  - 결과를 로그 탭뿐 아니라 배포 탭 하단에 유지.

구현 방향:

- `BulkCopy`에 `previewFile()` / `previewFolder()` 또는 `dryRun` 옵션을 추가한다.
- `DeploySection`이 마지막 실행 결과를 state로 들고 렌더링한다.
- `Notice`는 요약만, 상세는 패널에 남긴다.

### P2. 공유 공간 운영 화면 개선

- 위치: `src/settings/SettingsTab.ts:120-135`
- 위치: `src/settings/SettingsTab.ts:232-266`
- 위치: `src/ui/panel/DeploySection.ts:165-185`

공유 공간 설정은 가능하지만, 멤버 구성과 배포 상태를 계속 운영하기에는 단순하다. 특히 실시간 토큰, 재배포 필요 여부, 멤버 변경 후 학생에게 반영됐는지가 UI에 더 명확히 드러나면 좋다.

권장 기능:

- 공유 공간별 상태 배지:
  - 미배포
  - 배포됨
  - 멤버 변경됨, 재배포 필요
  - 실시간 토큰 만료 예정/만료
- 멤버 선택 UI 개선:
  - 전체 선택/해제.
  - 검색.
  - 반/모둠 프리셋.
- 배포 후 학생별 shares 기록 성공 여부 표시.

구현 방향:

- `SharedSpace`에 `lastDeployedAt`, `lastMemberSnapshot`, `lastTokenIssuedAt` 같은 운영 메타데이터를 추가한다.
- `deployShared()` 결과를 구조화해 UI가 학생별 성공/실패를 표시할 수 있게 한다.

## 학생 UX 제안

### P2. 학생 홈 화면 단순화

- 위치: `src/settings/SettingsTab.ts:315-347`
- 관련 위치: `src/ui/RoleSetupModal.ts:40-59`

학생 모드는 비교적 단순하지만, 설정 탭에는 연결 정보가 내부 용어 중심으로 표시된다. 학생 입장에서는 "내가 제대로 연결됐나", "마지막으로 선생님과 동기화됐나", "공유 폴더가 들어왔나"가 더 중요하다.

권장 UX:

- 학생 패널 첫 화면:
  - 내 이름 / 학급.
  - 연결 상태.
  - 마지막 동기화.
  - 공유 폴더 수.
  - "초대 코드 다시 붙여넣기" 버튼.
- CouchDB URL, Mirror DB, 계정은 고급 정보로 접기.

기대 효과:

- 학생이 설정값을 건드릴 위험 감소.
- 교사가 원격으로 안내하기 쉬워짐.

### P2. 초대 실패/만료 대응 안내

- 위치: `src/main.ts:340-367`
- 위치: `src/ui/InviteModal.ts:25-75`

초대 코드에는 만료가 없고 비밀번호 재발급으로 무효화되는 구조다. 보안 경고는 초대 모달에 잘 들어가 있다. 다만 학생이 옛 초대를 붙여넣었을 때는 "해석 실패" 또는 연결 실패로만 느껴질 수 있다.

권장 UX:

- 초대 파싱 실패와 인증 실패를 구분해 안내.
- 인증 실패 시:
  - "선생님이 초대를 재발급했을 수 있습니다. 새 QR/코드를 요청하세요."
- 교사용 초대 모달에는 "학생이 이미 설정했다면 새 코드로 다시 적용해야 함" 안내 추가.

## 피드백 레이어 기능 제안

### P2. 전체 미해결 피드백함

- 위치: `src/ui/panel/FeedbackSection.ts:51-84`

현재 피드백 탭은 활성 노트 기준으로 목록을 보여준다. 교사 입장에서는 학생별로 흩어진 노트의 미해결 피드백을 한 번에 보는 화면이 더 중요할 수 있다.

권장 기능:

- 전체 미해결 피드백 보기.
- 학생별, 공유 공간별, 노트별 필터.
- 최근 피드백, 해결됨 숨기기.
- "위치로" 클릭 시 해당 학생 폴더/공유 노트 열기.

구현 방향:

- `FeedbackStore`에 전체 인덱스 조회 API 추가.
- `FeedbackSection`에 "현재 노트 / 전체" 토글 추가.
- 교사 모드에서는 학생별 그룹핑을 기본으로 둔다.

### P3. 피드백 답글/상태 확장

현재 피드백은 생성, 위치 이동, 해결, 삭제 중심이다. 수업 운영에서는 짧은 답글이나 확인 상태가 있으면 더 자연스럽다.

권장 기능:

- 답글 스레드.
- 학생이 "확인함" 표시.
- 교사가 "다시 확인 필요"로 되돌리기.
- 피드백별 작성자 역할/대상 표시 강화.

## 설정/안전성 UX 제안

### P2. 인라인 검증 강화

- 위치: `src/settings/SettingsTab.ts:546-568`

폴더 경로 검증은 이미 들어가 있다. 추가로 아래 항목은 초대/배포 전에 막는 편이 안전하다.

권장 검증:

- 중복 `studentId`.
- 중복 `username`.
- 중복 `remoteDb`.
- 학생 폴더 간 겹침.
- 학생 폴더와 공유 폴더의 의도치 않은 겹침.
- CouchDB URL 형식.
- `Yjs 서버 URL`이 `wss://`가 아닌 경우 경고.
- `realtimeEnabled=true`인데 서버 URL 또는 토큰/공간 시크릿이 비어 있는 경우 경고.

구현 방향:

- `validateSettings(settings)` 유틸을 만들고 설정 탭, 배포, 진단에서 함께 사용한다.
- 경고는 `Notice`뿐 아니라 설정 행 아래에 지속 표시한다.
- 위험한 상태에서는 관련 CTA 버튼을 비활성화한다.

### P3. 파괴적/위험 작업의 확인 범위 확장

- 위치: `src/settings/SettingsTab.ts:289-299`
- 위치: `src/settings/SettingsTab.ts:512-534`

서버 데이터 초기화는 확인 모달이 잘 되어 있다. 반면 학생 카드 삭제는 즉시 실행된다. 학생 설정 삭제가 곧 서버 DB 삭제는 아니더라도, 운영 중에는 동기화 링크가 사라지는 효과가 있으므로 실수 방지가 필요하다.

권장 UX:

- 학생 삭제 확인 모달.
- 공유 공간 삭제 확인 모달.
- 삭제 시 "서버 데이터는 유지됨 / 동기화 링크만 제거됨" 명확히 표시.
- 서버 데이터까지 삭제하려면 별도 관리 탭으로 안내.

## 결론

Class Sync의 동기화/보안/실시간 기능은 베타 제품으로 이미 강한 차별점이 있다. 지금 가장 필요한 것은 기능을 더 넓히는 것이 아니라, 교사가 첫 설정을 성공하고 수업 중 문제를 스스로 해석할 수 있게 만드는 운영 UX다.

우선순위는 "온보딩 마법사", "액션형 대시보드", "학생 명단 일괄 추가" 순서가 적절하다. 이 세 가지가 들어가면 플러그인의 체감 완성도가 크게 올라가고, 베타 피드백도 동기화 엔진 자체보다 실제 수업 흐름에 가까운 방향으로 모일 가능성이 높다.

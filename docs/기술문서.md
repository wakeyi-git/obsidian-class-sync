# Obsidian 학급 양방향 노트 동기화 플러그인 기술 문서

## 1. 문서 목적

이 문서는 Obsidian 환경에서 교사용 vault의 학생별 폴더와 학생 개인 vault를 양방향으로 동기화하는 독립 플러그인 시스템의 기술 설계를 정의한다.

본 플러그인은 하나의 Obsidian 플러그인으로 배포되며, 사용자는 초기 설정에서 역할을 선택한다.

text id="zv1keo" 역할: - Student Mode - Teacher Mode 

선택한 역할에 따라 활성화되는 기능과 UI가 달라진다.

본 플러그인의 목표는 다음과 같다.

1. 학생은 자신의 Obsidian vault에서 평소처럼 노트를 작성한다.
2. 교사는 하나의 Obsidian vault 안에서 학생별 폴더를 관리한다.
3. 교사용 vault의 학생A/ 폴더는 학생 A의 vault와 양방향 동기화된다.
4. 학생이 만든 파일은 교사용 vault의 해당 학생 폴더에 나타난다.
5. 교사가 학생 폴더 안에 만든 파일은 해당 학생 vault에 나타난다.
6. 교사는 학생 폴더 안에서 파일을 생성, 이동, 수정할 수 있다.
7. 학생도 자신의 vault 안에서 파일을 생성, 이동, 수정할 수 있다.
8. 학생들이 같은 파일명을 사용해도 교사용 vault에서는 학생별 폴더로 분리되어 충돌하지 않는다.
9. 학생별 데이터와 권한은 서버 권한으로 분리한다.
10. 파일 단위 near-real-time 양방향 동기화를 기본 제공한다.
11. 글자 단위 실시간 공동 편집은 확장 기능으로 설계한다.
12. 시스템은 특정 기존 Obsidian 동기화 플러그인에 의존하지 않는다.

## 1.5 구현 현황 (최종, 2026-06-04 기준)

> 이 문서의 아래 본문(§2~§29)은 **초기 설계 사양**이다. 실제 구현은 그 설계를 따르되 여러 부분에서
> 확장·변경됐다. 이 절이 **최종 구현 기준**이며, 본문과 다를 경우 이 절을 우선한다. 사용자용 개요는
> [README.md](../README.md)(영어) / [README.ko.md](../README.ko.md)(한국어)를 참고한다.

**배포/플랫폼**
- 단일 플러그인 `class-sync`. **minAppVersion 1.11.4**(Secret Storage API). 데스크톱·모바일 모두 지원.
- 빌드: `tsc + esbuild`(production minify). 릴리스 CI에서 `npm run test` + i18n 중복키 검사 게이트.
- i18n: 한국어 원문을 키로 쓰는 `t()` + 영문 맵(`src/i18n/en.ts`), 언어 자동/ko/en.

**동기화 엔진**
- 클라이언트 **PouchDB(`pouchdb-browser`)** ↔ 서버 **CouchDB**. live replication(retry) + changes feed.
- 모바일 CORS는 `src/core/couch/obsidianFetch.ts`(Obsidian `requestUrl`)로 우회.
- 무거운 시작 작업(replication)은 `onLayoutReady` 이후로 지연(시작 속도). 백그라운드 파일 쓰기는 `Vault.process`.
- **상태 DB(`class_sync_status`)는 사용하지 않는다.** 상태(마지막 업/다운로드·충돌 수·오류)는 런타임에 계산해
  대시보드/진단에 표시한다(영속 상태 DB 없음).

**폴더/정책 기본값(설정 가능)**
- 보관 폴더 기본 **`_삭제됨/`**, 충돌 폴더 기본 **`_충돌/`**(본문의 `.deleted`/`.conflicts`는 옛 이름).
- 삭제 정책 기본 **archive**, 충돌 정책 **preserve-local**(원격본을 `_충돌/`에 보존, 충돌 목록 UI로 해소).
- 충돌 시 내 편집이 덮일 위험이면 `_충돌/<파일>.내편집.md`로 백업. 첨부 충돌도 원격 바이너리를 `_충돌/`에 보존.

**오프라인 삭제 정합(설계의 manifest를 대체·강화)**
- §8.4의 per-DB `manifest` 문서 대신, 링크별 **`_local/manifest`**(원격 미복제) 스냅샷을 둔다(`LinkManifest`).
- 전체 동기화 시 "내용 검증된 보유 기준선"과 비교해 사라진 파일만 tombstone. **localRoot 변경/기준선 없음이면 스킵**,
  **대량 삭제 임계치**(기본 `max(5, 50%)`, 설정 `deleteReconcileMax`로 절대값 지정)로 폴더 오설정 사고를 막는다.
- 수동 동기화 방향 분리: `up`=push만, `down`=pull만, `both`=pull→삭제정합→push(원격 최신 반영 후 판단).

**공유 폴더 + 실시간 공동 편집(설계 §6/§19를 구현)**
- 교사 설정의 *공유 공간*(전용 DB `share_<id>` + 멤버 권한)을 **배포**하면 `shares`/`rtconfig` 문서로 학생에 전파.
- 실시간은 **공유 폴더 문서에서만** 동작(개인 미러 노트는 파일 단위 동기화). room = **`class_<classId>/share/<spaceId>/<dbPath>`**.
- 마크다운: Yjs `y-codemirror.next`(CM6) 글자 단위. **Excalidraw**: `y-excalidraw` 요소 단위(`.excalidraw.md`만 — 스냅샷이
  markdown 업로드 경로를 타야 전파). 세션 종료/주기 스냅샷으로 비실시간 멤버에 영속.
- **참가자 칩**: 편집 영역 우하단에 이름·색을 상시 표시(마우스 없는 태블릿/모바일 대응). 마크다운·Excalidraw 색을
  `clientColor(clientId)` 공식으로 통일(커서·칩 일치).

**실시간 보안**
- 토큰은 **공유 공간별 HMAC 서명 토큰**(payload `{c:classId, s:spaceId, e?:exp}`). 서버([docs/Yjs 서버 운영/server.js](Yjs%20서버%20운영/server.js))가
  서명 + room prefix(`class_<c>/share/<s>/`) + 만료를 검증 → 유출돼도 그 공간 room만 접근. 듀얼모드: `YJS_SECRET`(HMAC)
  / `YJS_TOKEN`(레거시 전역). placeholder/짧은 시크릿이면 서버 기동 거부.
- 교사의 **Yjs 토큰·공간 시크릿은 Obsidian Secret Storage**에 저장(`data.json` 평문 아님, 업그레이드 시 자동 이전).
  TTL은 `yjsTokenTtlDays`, 공간 토큰 만료는 재배포로 회전.

**피드백 레이어(§19.5 구현)**
- 본문 미수정 앵커 댓글. 대상 노트가 속한 DB(개인/공유)에 `feedback:` 문서로 저장(파일 아님). 패널에서 목록·이동·해결,
  교사용 **전체 미해결 피드백함** 토글(학생·노트 라벨 + 위치로 이동).

**교사 운영 UX(설계 이후 추가)**
- 통합 사이드 패널(탭: **시작하기**·피드백·배포·동기화 상태·관리·로그).
- **온보딩 마법사**(‘시작하기’ 체크리스트), **학생 명단 일괄 추가**(붙여넣기/CSV + 중복 검증), **배포 탭**(경로 선택 +
  **미리보기(dry-run)** + 학생별 결과·실패만 재시도), **액션형 대시보드**(조치 카드 + 좁은 화면 카드), **설정 인라인 검증**
  (중복 ID/URL/wss/폴더 겹침), 공유 공간 **운영 배지**(미배포/배포됨/멤버 변경-재배포 필요).
- 학생/공유 공간 삭제 확인 모달, 학생 설정 홈 단순화(내부 용어는 ‘고급 정보’로 접기).

**초대/계정 보안**
- QR/딥링크 초대(base64). 자체 만료 없음 — 유출 시 **‘비밀번호 재발급’**(재프로비저닝)으로 이전 초대 즉시 무효화.
- 학생은 최소권한 계정(자기 mirror DB만). 설정 내보내기는 자격증명·시크릿·기기값 제외.

**실제 디렉터리 구조**는 [README.md](../README.md)의 “Architecture” 절을 참고(본문 §23.1의 트리는 초기 안). 주요 위치:
`src/core/realtime/`(RealtimeManager·editorBinding·excalidrawBinding·presenceChips·spaceToken), `src/core/sync/`,
`src/core/feedback/`, `src/core/secret.ts`, `src/ui/panel/`, `src/settings/`.

하나의 플러그인 내부는 공통 core와 역할별 mode로 나뉜다.

text id="4s0y1b" Class Sync Plugin ├─ Core Services │  ├─ CouchDB 연결 │  ├─ changes feed 구독 │  ├─ 문서 모델 │  ├─ 경로 정규화 │  ├─ 파일 hash 계산 │  ├─ offline queue │  ├─ 충돌 처리 │  ├─ 삭제/보관 정책 │  ├─ remote apply guard │  └─ 상태 로그 ├─ Student Mode │  ├─ 학생 vault 변경 감지 │  ├─ 학생 mirror DB 업로드 │  ├─ 교사 변경사항 수신 │  ├─ 파일/폴더 생성, 이동, 수정, 삭제 반영 │  └─ 학생용 상태 UI └─ Teacher Mode    ├─ 학생별 폴더 변경 감지    ├─ 학생별 mirror DB 업로드    ├─ 학생 변경사항 수신    ├─ 학생별 상태 대시보드    ├─ 전체/선택 학생 파일 복사 명령    └─ 충돌 관리 UI 

중앙 서버로는 CouchDB 또는 CouchDB 호환 저장소를 사용한다.

> **기술 선택 (2026-05-31 확정):** 서버는 CouchDB(시놀로지 NAS Docker), 클라이언트는
> **PouchDB(`pouchdb-browser`)** 로 구현한다. PouchDB가 오프라인 큐 / 충돌 / changes /
> replication을 내장 제공하므로 직접 구현 공수를 크게 줄인다. 모바일(Android)의 CORS 제약은
> Obsidian `requestUrl` 기반 fetch shim으로 우회한다 (§23.4 참고).
> 학생별 격리는 CouchDB DB별 `_security`로 보장한다.
> 글자 단위 실시간 공동 편집(§19)은 저장 백엔드와 독립적인 Yjs 확장 레이어로, **공유 폴더 한정으로 구현 완료**
> (마크다운 + Excalidraw, 공간별 HMAC 토큰, 참가자 칩). 최종 동작은 §1.5 참고.

예:

text id="k0cryw" 명령: 현재 파일을 전체 학생에게 복사  원본:   TeacherVault/템플릿/오늘의_활동.md  결과:   TeacherVault/학생A/오늘의_활동.md   TeacherVault/학생B/오늘의_활동.md   TeacherVault/학생C/오늘의_활동.md 

이후 각 학생별 mirror DB를 통해 학생 기기에 반영된다.

## 5. 역할 기반 실행 모델

## 5.1 역할 선택

플러그인은 최초 설정 시 다음 중 하나의 역할을 선택한다.

text id="ijqdjy" Student Mode Teacher Mode 

Student Mode 설정 예시:

json id="a7dsr4" {   "role": "student",   "classId": "class_2026_1",   "userId": "student_a",   "displayName": "학생A",   "deviceId": "student_a_tablet_01",   "remoteDb": "mirror_student_a",   "localRoot": "" } 

Teacher Mode 설정 예시:

json id="16r351" {   "role": "teacher",   "classId": "class_2026_1",   "userId": "teacher",   "displayName": "교사",   "students": [     {       "studentId": "student_a",       "studentName": "학생A",       "remoteDb": "mirror_student_a",       "localRoot": "학생A"     },     {       "studentId": "student_b",       "studentName": "학생B",       "remoteDb": "mirror_student_b",       "localRoot": "학생B"     }   ] } 

## 5.2 역할별 기능 활성화

플러그인 로딩 시 설정의 role 값을 읽고 해당 mode만 활성화한다.

ts id="w4x1jr" async onload() {   await this.loadSettings();    this.core = new CoreServices(this.app, this.settings);    if (this.settings.role === "student") {     this.mode = new StudentMode(this.app, this.core, this.settings);   }    if (this.settings.role === "teacher") {     this.mode = new TeacherMode(this.app, this.core, this.settings);   }    await this.mode.start(); } 

## 5.3 역할 변경

역할 변경 시 기존 mode를 정지하고 새 mode를 시작한다.

ts id="vr2nvb" async switchRole(nextRole: "student" | "teacher") {   await this.mode?.stop();    this.settings.role = nextRole;   await this.saveSettings();    if (nextRole === "student") {     this.mode = new StudentMode(this.app, this.core, this.settings);   } else {     this.mode = new TeacherMode(this.app, this.core, this.settings);   }    await this.mode.start(); } 

역할 변경 시 주의할 점:

text id="36j9e9" - 기존 changes feed 연결 종료 - offline queue flush 또는 중지 - 역할별 ribbon icon 갱신 - 역할별 command 재등록 - 역할별 setting UI 재렌더링 

## 5.4 역할 선택은 보안 경계가 아님

역할 선택은 로컬 UI와 기능 분기를 위한 설정이다.  
학생이 로컬 설정 파일을 수정해 role을 teacher로 바꾸는 것을 클라이언트만으로 완전히 막을 수 없다.

따라서 실제 보안은 반드시 CouchDB 계정 권한으로 보장한다.

예:

text id="8wi119" 학생A 계정:   mirror_student_a 읽기/쓰기   mirror_student_b 접근 불가   mirror_student_c 접근 불가  교사 계정:   mirror_student_a 읽기/쓰기   mirror_student_b 읽기/쓰기   mirror_student_c 읽기/쓰기   class_sync_status 읽기/쓰기 

## 6. 권장 vault 구조

## 6.1 교사용 vault

교사용 vault는 학생별 폴더를 최상위 또는 지정된 root 아래에 둔다.

최상위 학생 폴더 방식:

text id="1fh8zo" TeacherVault/ ├─ 학생A/ │  ├─ 과제.md │  ├─ 피드백.md │  └─ 수업/1차시.md ├─ 학생B/ │  ├─ 과제.md │  └─ 수업/1차시.md ├─ 학생C/ │  └─ 질문.md └─ 템플릿/    └─ 오늘의_활동.md 

학생 폴더 root를 따로 두는 방식:

text id="jxu60h" TeacherVault/ ├─ 학생/ │  ├─ 학생A/ │  ├─ 학생B/ │  └─ 학생C/ └─ 템플릿/    └─ 오늘의_활동.md 

이 경우 Teacher Mode 설정에서 localRoot를 다음처럼 지정한다.

json id="mcgvov" {   "studentId": "student_a",   "studentName": "학생A",   "remoteDb": "mirror_student_a",   "localRoot": "학생/학생A" } 

## 6.2 학생용 vault

학생용 vault는 자신의 vault root 전체가 동기화 root가 된다.

text id="2ts4sm" StudentA Vault/ ├─ 과제.md ├─ 피드백.md ├─ 수업/ │  └─ 1차시.md └─ 첨부파일/ 

필요하다면 학생 측에서도 특정 폴더만 동기화 root로 지정할 수 있다.

json id="hm947f" {   "localRoot": "학급노트" } 

이 경우 매핑은 다음과 같다.

text id="b9tsn0" DB path: 과제.md 학생 측: StudentA Vault/학급노트/과제.md 교사 측: TeacherVault/학생A/과제.md 

## 7. 데이터베이스 구조

## 7.1 학생별 mirror DB

학생마다 하나의 mirror DB를 둔다.

text id="i4cohy" mirror_student_a mirror_student_b mirror_student_c 

각 mirror DB는 해당 학생 vault와 교사용 vault의 해당 학생 폴더를 연결한다.

## 7.2 상태 DB

선택적으로 교사용 상태 DB를 둔다.

text id="blvzkh" class_sync_status 

용도:

text id="cwbgsj" - 학생별 마지막 접속 시각 - 마지막 업로드 시각 - 마지막 다운로드 시각 - 충돌 목록 - 오류 로그 - 교사 편의 명령 실행 기록 

## 7.3 문서 타입

mirror DB의 문서 타입:

text id="x755cs" note asset tombstone manifest conflict 

## 8. Mirror 문서 모델

## 8.1 note 문서

json id="cfwjs1" {   "_id": "note:수업/1차시.md",   "type": "note",   "schemaVersion": 1,   "classId": "class_2026_1",   "studentId": "student_a",   "path": "수업/1차시.md",   "content": "# 1차시\n내용...",   "contentHash": "sha256...",   "ctime": 1770000000000,   "mtime": 1770000100000,   "deleted": false,   "version": 7,   "lastModifiedBy": "teacher",   "lastModifiedRole": "teacher",   "lastModifiedDeviceId": "teacher_macbook",   "updatedAt": "2026-05-31T12:00:00+09:00" } 

path는 학생 vault 기준 상대 경로다.  
교사용 vault에서는 학생별 localRoot 아래에 매핑된다.

text id="pforie" path = 수업/1차시.md  Student Mode:   {studentLocalRoot}/수업/1차시.md  Teacher Mode:   {student.localRoot}/수업/1차시.md 

## 8.2 asset 문서

첨부파일은 CouchDB attachment 사용을 권장한다.

json id="7r59ke" {   "_id": "asset:첨부파일/photo.png",   "type": "asset",   "schemaVersion": 1,   "classId": "class_2026_1",   "studentId": "student_a",   "path": "첨부파일/photo.png",   "mime": "image/png",   "size": 120394,   "contentHash": "sha256...",   "deleted": false,   "lastModifiedBy": "student_a",   "lastModifiedRole": "student",   "lastModifiedDeviceId": "student_a_tablet_01",   "updatedAt": "2026-05-31T12:00:00+09:00" } 

## 8.3 tombstone 문서

파일 삭제 시 실제 문서를 즉시 제거하지 않고 삭제 기록을 남긴다.

json id="e75yl1" {   "_id": "note:과제.md",   "type": "note",   "studentId": "student_a",   "path": "과제.md",   "deleted": true,   "deleteMode": "archive",   "deletedAt": "2026-05-31T12:10:00+09:00",   "deletedBy": "teacher",   "deletedByRole": "teacher",   "lastKnownContentHash": "sha256..." } 

## 8.4 manifest 문서

json id="7e4qt7" {   "_id": "manifest",   "type": "manifest",   "schemaVersion": 1,   "classId": "class_2026_1",   "studentId": "student_a",   "pluginVersion": "0.1.0",   "deviceId": "student_a_tablet_01",   "role": "student",   "lastFullScanAt": "2026-05-31T12:00:00+09:00",   "lastSeenAt": "2026-05-31T12:05:00+09:00" } 

## 8.5 conflict 문서

동시 수정 충돌이 발생하면 conflict 문서를 남긴다.

json id="hj9iei" {   "_id": "conflict:과제.md:20260531T120000",   "type": "conflict",   "studentId": "student_a",   "path": "과제.md",   "localVersion": {     "modifiedBy": "teacher",     "contentHash": "sha256-local",     "updatedAt": "2026-05-31T12:00:00+09:00"   },   "remoteVersion": {     "modifiedBy": "student_a",     "contentHash": "sha256-remote",     "updatedAt": "2026-05-31T12:00:01+09:00"   },   "resolution": "unresolved",   "createdAt": "2026-05-31T12:00:02+09:00" } 

## 9. 경로 매핑 규칙

## 9.1 DB path

DB에 저장되는 path는 항상 학생 vault 기준 상대 경로다.

허용:

text id="ohh3bw" 과제.md 수업/1차시.md 첨부파일/photo.png 

금지:

text id="gcnzl9" ../secret.md /absolute/path.md C:\Users\... .obsidian/plugins/... 

## 9.2 Student Mode path 매핑

text id="wsk6tz" localRoot = "" DB path = 과제.md local path = 과제.md 

또는:

text id="7m2cw3" localRoot = 학급노트 DB path = 과제.md local path = 학급노트/과제.md 

## 9.3 Teacher Mode path 매핑

text id="bdax2t" student.localRoot = 학생A DB path = 과제.md local path = 학생A/과제.md 

중첩 경로:

text id="sio4ng" student.localRoot = 학생A DB path = 수업/1차시.md local path = 학생A/수업/1차시.md 

## 9.4 학생별 폴더 밖 변경 무시

Teacher Mode는 학생별 localRoot 내부의 변경만 mirror DB에 반영한다.

예:

text id="n08cwq" TeacherVault/템플릿/오늘의_활동.md 

은 자동 동기화하지 않는다.

교사가 템플릿을 학생에게 보내려면 편의 명령을 사용해 학생 폴더 안으로 복사한다.

## 10. 동기화 방향

## 10.1 학생 → 교사

text id="q6g6cr" StudentA Vault/과제.md 수정 → Student Mode가 변경 감지 → mirror_student_a의 note:과제.md 갱신 → Teacher Mode가 changes feed 수신 → TeacherVault/학생A/과제.md 갱신 

## 10.2 교사 → 학생

text id="uf4ctb" TeacherVault/학생A/피드백.md 생성 → Teacher Mode가 학생A localRoot 변경 감지 → mirror_student_a의 note:피드백.md 생성 → Student Mode가 changes feed 수신 → StudentA Vault/피드백.md 생성 

## 10.3 이동과 이름 변경

파일 이동 또는 이름 변경은 다음처럼 처리한다.

text id="36tet8" old path tombstone 생성 new path note/asset 생성 

예:

text id="rjvaad" TeacherVault/학생A/과제.md → TeacherVault/학생A/완료/과제.md 

DB 처리:

text id="ekll0s" note:과제.md       → deleted=true note:완료/과제.md  → content 저장 

학생 측 반영:

text id="rqwka6" StudentA Vault/과제.md → StudentA Vault/완료/과제.md 

## 10.4 삭제

삭제는 기본적으로 직접 삭제가 아니라 보관 처리한다.

교사가 삭제:

text id="qqfpqz" TeacherVault/학생A/과제.md 삭제 → mirror_student_a note:과제.md deleted=true → StudentA Vault/.deleted/과제.md 로 이동 

학생이 삭제:

text id="4jixgz" StudentA Vault/과제.md 삭제 → mirror_student_a note:과제.md deleted=true → TeacherVault/학생A/.deleted/과제.md 로 이동 

설정 가능한 삭제 정책:

text id="7a3m1w" archive: 상대방에서 .deleted로 이동 propagate-delete: 상대방에서도 삭제 ignore-delete: 삭제 이벤트 무시 

기본값:

text id="0e5jnw" archive

## 12. Teacher Mode 기능 요구사항

## 12.1 교사 설정

json id="2u3asn" {   "role": "teacher",   "classId": "class_2026_1",   "userId": "teacher",   "displayName": "교사",   "deviceId": "teacher_macbook",   "couchdbUrl": "https://nas.example.com/couchdb",   "username": "teacher",   "password": "********",   "students": [     {       "studentId": "student_a",       "studentName": "학생A",       "remoteDb": "mirror_student_a",       "localRoot": "학생A"     },     {       "studentId": "student_b",       "studentName": "학생B",       "remoteDb": "mirror_student_b",       "localRoot": "학생B"     }   ],   "autoSync": true,   "deletePolicy": "archive",   "conflictPolicy": "preserve-local" } 

## 12.2 학생별 폴더 감시

Teacher Mode는 각 학생의 localRoot를 감시한다.

감시 대상:

text id="f1eweh" 학생A/** 학생B/** 학생C/** 

감시 제외:

text id="as3l8y" .obsidian/** .trash/** .deleted/** .conflicts/** 템플릿/** 

학생별 폴더 밖의 파일은 자동 동기화하지 않는다.

## 12.3 학생별 mirror DB 구독

Teacher Mode는 학생별 mirror DB의 changes feed를 구독한다.

text id="xpamhv" mirror_student_a/_changes mirror_student_b/_changes mirror_student_c/_changes 

원격 변경이 들어오면 해당 학생 localRoot 아래에 반영한다.

## 12.4 교사 → 학생 변경 업로드

교사가 학생 폴더 안에서 파일을 생성, 수정, 이동, 삭제하면 해당 학생 mirror DB에 반영한다.

예:

text id="5bxfar" TeacherVault/학생A/피드백.md 생성 → mirror_student_a note:피드백.md 생성 

text id="1x2iwo" TeacherVault/학생B/과제.md 수정 → mirror_student_b note:과제.md 갱신 

## 12.5 전체/선택 학생 파일 복사 명령

별도 배포 폴더를 두지 않기 때문에 Teacher Mode는 편의 명령을 제공한다.

명령:

text id="lg6k7h" 현재 파일을 전체 학생에게 복사 현재 파일을 선택 학생에게 복사 선택한 폴더를 전체 학생에게 복사 템플릿에서 학생별 파일 생성 

동작 예:

text id="ha21o1" 원본:   템플릿/오늘의_활동.md  명령:   전체 학생에게 복사  결과:   학생A/오늘의_활동.md   학생B/오늘의_활동.md   학생C/오늘의_활동.md 

이후 일반 양방향 미러링에 의해 각 학생 vault에 전달된다.

## 13. 권한 설계

## 13.1 학생 계정

학생 A 계정 권한:

text id="kdm1nw" mirror_student_a: read/write mirror_student_b: 접근 불가 mirror_student_c: 접근 불가 class_sync_status: 권장하지 않음 또는 제한적 write 

학생은 자신의 mirror DB에만 접근할 수 있어야 한다.

## 13.2 교사 계정

교사 계정 권한:

text id="9i7df0" mirror_student_a: read/write mirror_student_b: read/write mirror_student_c: read/write class_sync_status: read/write 

교사는 모든 학생의 mirror DB에 접근한다.

## 13.3 역할 위조 방지

로컬 role 설정은 신뢰하지 않는다.  
학생이 role: teacher로 바꾸더라도 서버 권한이 없으면 교사용 작업이 실패해야 한다.

Teacher Mode 진입 시 다음 작업을 수행한다.

text id="8lfzll" - 각 학생 mirror DB read 권한 테스트 - 적어도 하나의 mirror DB write 권한 테스트 - status DB 사용 시 write 권한 테스트 

Student Mode 진입 시 다음 작업을 수행한다.

text id="9j7sl1" - 자기 mirror DB read/write 권한 테스트 

## 14. 충돌 처리

## 14.1 충돌 발생 조건

충돌은 다음 경우에 발생한다.

text id="7v7tek" - 교사와 학생이 같은 파일을 동시에 수정 - 한쪽은 파일을 이동하고 다른 쪽은 기존 위치에서 수정 - 한쪽은 삭제하고 다른 쪽은 수정 - 오프라인 상태에서 양쪽이 같은 파일을 수정 후 재연결 

## 14.2 충돌 판단 기준

각 파일에 대해 마지막 동기화 상태를 저장한다.

json id="x9qya5" {   "path": "과제.md",   "lastSyncedHash": "sha256-base",   "localHash": "sha256-local",   "remoteHash": "sha256-remote",   "lastSyncedVersion": 7 } 

판단:

text id="ce0bwy" localHash == lastSyncedHash   → remote 적용 가능  remoteHash == lastSyncedHash   → local 업로드 가능  localHash != lastSyncedHash AND remoteHash != lastSyncedHash   → conflict 

## 14.3 충돌 파일 생성

Teacher Mode 충돌:

text id="rgfs4u" 학생A/.conflicts/과제.teacher-20260531-1200.md 학생A/.conflicts/과제.student-20260531-1200.md 

Student Mode 충돌:

text id="wzq6yo" .conflicts/과제.local-20260531-1200.md .conflicts/과제.remote-20260531-1200.md 

## 14.4 기본 충돌 정책

기본값:

text id="zkbh1i" preserve-local 

의미:

text id="r64o75" 로컬 파일을 덮어쓰지 않는다. 원격 변경은 .conflicts에 보관한다. 사용자가 수동으로 병합한다. 

설정 가능한 정책:

text id="68ruyg" preserve-local prefer-teacher prefer-student keep-both 

## 15. 삭제와 보관 정책

## 15.1 기본 삭제 정책

기본값:

text id="iqwnvf" archive 

삭제된 파일은 상대방에서 실제 삭제하지 않고 .deleted로 이동한다.

예:

text id="6mrgh2" 학생이 과제.md 삭제 → 교사: 학생A/.deleted/과제.md 

text id="5v9j8q" 교사가 학생A/과제.md 삭제 → 학생: .deleted/과제.md 

## 15.2 propagate-delete

선택적으로 실제 삭제를 전파할 수 있다.

text id="bddnd3" deletePolicy = propagate-delete 

이 정책은 데이터 손실 위험이 있으므로 기본값으로 사용하지 않는다.

## 15.3 ignore-delete

삭제 이벤트를 무시한다.

text id="n2292o" deletePolicy = ignore-delete 

이 경우 상대방의 파일은 그대로 유지된다.

## 16.1 문제

## 26.4 학생에게 안내할 기본 규칙

text id="8pbn2e" 이 vault 또는 지정된 학급노트 폴더는 교사용 학생 폴더와 동기화된다. 파일을 만들면 교사에게 보인다. 교사가 만든 파일도 내 vault에 나타난다. 교사와 동시에 같은 파일을 수정하면 충돌 파일이 생길 수 있다. 파일 삭제는 즉시 사라지지 않고 .deleted에 보관될 수 있다. 동기화 상태에 오류가 있으면 전체 동기화를 실행한다.

## 28. MVP 성공 기준

초기 성공 기준은 다음과 같다.

1. 하나의 플러그인에서 Student Mode와 Teacher Mode를 선택할 수 있다.
2. Student Mode에서는 하나의 mirror DB와 학생 vault root 또는 지정 localRoot가 동기화된다.
3. Teacher Mode에서는 여러 학생 폴더와 여러 mirror DB가 매핑된다.
4. 학생이 만든 과제.md가 교사용 vault의 학생A/과제.md로 나타난다.
5. 교사가 학생A/피드백.md를 만들면 학생 A vault의 피드백.md로 나타난다.
6. 학생 A와 학생 B가 같은 이름의 과제.md를 작성해도 교사용 vault에서 충돌하지 않는다.
7. 파일 수정이 양방향으로 반영된다.
8. 파일 생성과 수정은 저장 후 1~3초 이내 또는 앱 재활성화 시 상대방에게 반영된다.
9. 삭제는 기본적으로 .deleted 폴더에 보관된다.
10. 동시 수정 충돌 시 .conflicts 폴더에 양쪽 버전이 보관된다.
11. 학생별 계정은 다른 학생 mirror DB에 접근할 수 없다.
12. 학생 계정으로 Teacher Mode를 선택해도 서버 권한 테스트에서 실패한다.
13. 네트워크가 끊겨도 재연결 후 누락분이 처리된다.
14. remote apply guard로 동기화 루프가 발생하지 않는다.
